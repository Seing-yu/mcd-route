在 WorkBuddy 里，它长这样

这是一个 Agent Skill —— 装进 WorkBuddy 后，你正常说话，它自己去调麦当劳 MCP 查数据、算账、给结论。下面是真实调用过程（节选，calculate-price 返回值单位是分）。

你
我晚上想吃麦当劳，点外送还是自己去店里？
麦门渠道官
稍等，我查一下你附近的店和两家渠道的价格、券。
query-nearby-stores city=北京 keyword=望京 beType=1
→ 5 家门店，distance 312~1215 米
query-meals storeCode=1950980 orderType=1 beType=1
→ 11 个分类 118 款餐品
query-store-coupons storeCode=1950980
→ 2 张券（11.9元麦辣鸡腿堡 / 19.9元王牌炸鸡任选2）
calculate-price 3 件商品 orderType=1 beType=1
→ price=4650（分）= ¥46.50
麦门渠道官
建议到店自取。
这一单到店到手价 ¥46.50，比外送少 —— 外送要加配送费和打包费，而你这单在到店渠道有 11.9 元券可用，能直接抵掉 10.6 元。

距离 312 米，按步行 5 分钟算，加上出餐 8 分钟，总共 13 分钟就能吃到。按每分钟 0.5 元折算，你的时间成本是 ¥6.50。

外送侧这次没查 —— 查外送需要你的配送地址，那是你的个人数据，我不会主动去拿。

你的数据去哪了

Token 不进仓库

仓库里只有占位符 ${MCD_MCP_TOKEN}，没有任何真实 Token。

真 Token 存在你自己的 ~/.workbuddy/ 目录，不在任何 git 仓库内。

官方规则第五条明确禁止把 Token 输入 AI 对话 —— 这个 Skill 从设计上就不走那条路。

这个页面不收集任何东西

纯静态单文件，零服务端、零数据库、零上传。

你拖动的每个参数都只在浏览器内存里算，刷新即消失，不发往任何服务器。

整个页面不加载任何第三方脚本或外部资源。

地址由你决定要不要给

查外送必须提供配送地址 addressId，那是你的个人数据。

Skill 不会主动索取，也不会把地址写进任何文件；你不给，它就只做到店侧并明说缺什么。

仓库自带的样例数据里，地址字段是门店公开地址或已脱敏。

以上三条不是口头承诺 —— selftest.py 里 137 项断言会扫描整个仓库，确认不存在真实 Token、手机号、身份证号、邮箱；parity_check.py 对拍网页与 CLI 两套实现，防止数字对不上。
