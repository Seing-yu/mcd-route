## 二、核心叙事（所有渠道统一用这一套）

### 一句话

> **同样是省一顿，聪明人已经在算「跑一趟值不值」。**

### 三个差异点（按说服力排序）

1. **券是绑商品、还分渠道的** —— 一张到店券在外送场景**根本用不了**。
   多数省钱助手会直接报出你用不上的低价。这是真实痛点，不是炫技。
2. **时间成本参数化** —— 同一顿餐，对不在乎时间的人和时薪 100 元的人**答案相反**。
   我们不输出一个固定答案，输出「对谁更划算」。
3. **保守计价** —— 券不叠加、缺失字段不估算、起送价不达标就明说不可下单。
   **宁可少报优惠，也不给假低价。**

### 可复现的证据

- 253 项自测 + 前后端 56 项对拍，CI 全绿
- 真实 MCP 调用（`mcp__mcd-mcp__*` 原生通道），快照在仓库里可查
- 在线试算页**零安装、零 Token、零采集**，点开就能玩
- Token 不进仓库、不下单、不领券，全程只读

**正文骨架**（700-1200 字，参照已有参赛实录的结构）：

```markdown
## 一、我为什么做这个

麦当劳 MCP 出来之后，参赛作品里大半都在做「怎么点最便宜」。
但我真正每天纠结的是另一件事：**今晚点外卖，还是自己跑一趟？**

## 二、这个题难在哪

三个真实的坑，都是我真调过接口才知道的：

1. **金额单位不统一** —— `calculate-price` 返回「分」，`query-meals` 返回「元」。
   混用会让每个金额差 100 倍。
2. **券是商品券，不是满减券** —— 券名里的「11.9 元」是用券价，
   抵扣额要拿菜单原价减出来。而且**券绑商品**，你买套餐，这张单品券就用不上。
3. **券还分渠道** —— 到店券在外送场景根本用不了。
   这才是最坑的：很多助手会直接报出一个你用不上的低价。

## 三、我的解法

取数交给 MCP，算术交给代码，表达交给 Agent。
**所有金额由代码算，模型不口算价格。**

核心是把「时间值多少钱」做成可调参数：

    到手总价 = 商品原价 − 可用券抵扣 + 配送费
    总成本   = 到手总价 + 时间成本（分钟数 × 时间单价）

同一顿餐，`--minute-cost 0` 和 `--minute-cost 1.67` 会给出相反的答案。
这不是 bug，是「时间对不同的人值不同的钱」。
```
